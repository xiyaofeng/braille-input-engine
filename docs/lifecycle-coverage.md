# Lifecycle paths, conditions and bounded evidence

This is a branch/ownership map, not a claim that every event or DOM topology has been verified. The 2026-10-12 P2 remediation corrects the previous table's overstatement: a single-attachment guard rejection did not establish overlapping-scope safety, and light-DOM focus tests did not establish Shadow DOM propagation. The 2026-10-17 follow-up covers the UI-control exclusion regression introduced by broader open-root admission. Mechanisms below are implemented; a V applies only to the combinations in the evidence table.

## State-modification paths

R1: old cleanup cannot delete callback input. R2: attachment-local loss releases only owned pressed IDs (a shared Chord Cell is still cancelled). R3: frozen flag, contributions and actual retry agree. R4: stale terminals are inert. R5: subscription registrations are independent. R6: accepted output occurs once. R7: explicit abandonment/fault/terminal cleanup follows the controller contract.

## REVIEW-04: real editable delivery in open Shadow DOM

Editable admission now descends through accessible open-root active elements at every sink write and again after beforeinput. Membership remains exact: an unregistered sibling in the same host is outside the group. No host is implicitly registered and focus/manual/always policy defaults are unchanged. Node.contains includes the node itself; its former separate equality check is redundant. Focus activation still saves and returns the same current value. These two equivalent simplifications keep the existing size growth gate without changing the baseline.

`tests/fixtures/editable-focus.ts` exercises 100 cases against actual editable sinks: four light/open target/UI layouts, input/textarea, direct and default-UI commit/retry, same-host nonmember, readonly/disabled, group destruction, detach, beforeinput focus loss/readonly/detach/cancel, plus ungrouped focus attachments. Every grouped case checks actual text, delivery, pending/retry and beforeinput/input counts. The fixture runs in source DOM, three browser engines across source/ESM/browser/IIFE, and extracted package ESM/CJS.

`tests/browser/editable-focus.spec.ts` additionally uses trusted KeyF then Space through real keyboard + editable + default UI, for four layouts × focus/manual/always × keyboard commit/UI commit/UI retry. Retry is an actual rejected write followed by recovery, with exactly one text insertion and one beforeinput/input pair.

Evidence covers one accessible open root and native input/textarea selection. It does not establish nested root/slot/delegatesFocus, closed roots, contenteditable shadow selection, cross-origin frames, OS blur, physical hardware, assistive technology or target-user coverage. M4 remains pending.
